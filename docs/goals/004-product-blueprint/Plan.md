# Goal 004 - Documentation plan

Seven dependency-ordered phases produce the reviewable design packet. All
phases are documentation/static-validation work; none executes or mutates the
analysis engine.

1. **Baseline gate** — verify clean synchronized `main` at the later packet-
   publication commit, with all four packet files tracked and the accepted
   Goal 003 baseline as an ancestor; confirm permitted paths and no unexpected
   mutations.
2. **Journey and promise** — describe the labelled-record-to-report journey,
   plain product promise, user-visible stops, and the primary/audit/machine
   output contract.
3. **Entity and data contracts** — define immutable ingest, CSV/CamtrapDP
   compatibility, audited repair preview, entity/effort/event resolution,
   named scales, and conservative deployment effort without writing schemas.
4. **Capability contract** — map modules to the exact tiers
   (`foundation`, `standard_profile`, `conditional`, `later_option`) and exact
   dispositions (`retain`, `refactor`, `quarantine`, `replace`, `new`), with
   fail-soft omission versus integrity-stop rules and one shared engine.
5. **Judbury and portability** — build the nine-station/13-physical/four-move
   no-grouping validation matrix for success and principled omission; specify
   the independent LocalMap file-manifest boundary and the second portability
   case for the software-product note.
6. **Roadmap and decisions** — order no more than eight development phases,
   record reversible versus Barry-owned decisions, preserve the current engine,
   and recommend (without writing or implementing) the next goal.
7. **Validate, review, stop** — run static path/vocabulary/whitespace checks,
   obtain one non-authoring read-only review, make at most one material repair,
   report residual uncertainty, and stop with execution outputs ready for
   orchestrator review and strategic publication review.
